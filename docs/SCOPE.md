# 边界声明：答什么，不答什么

> catalog 的 `open` 是「**待答**」（已立目、还没答案），本页把另两类分开：
> 「**永不答**」（论证过不答，除非第一性依据变了）与「**留缝**」（答案已交付，但策略由项目裁）。
> 三类分开，是为了让"还没做"和"不做"不再混装——这是 2026-10-26 七维体检（维度 1）指出的缺口。

## 一、永不答（论证过，改判需新 ADR）

| 问题 | 为什么不答 | 依据 |
|---|---|---|
| 部署拓扑（单体↔微服务切换、拆库拆表） | 拆库与团队组织在框架控制面之外，任何承诺都无法被测试守护 | ADR-004 |
| 远程调用 / 服务间通信 | Spring 自带客户端已解决；框架介入只会增加条件分支——条件分支是非确定性之源 | ADR-004 |
| API 文档超出四条增值点的部分 | schema 对齐 / traceId / 动作同源 / 端点豁免之外是文档工具自身的领域 | ADR-013 |
| 业务逻辑 / 领域建模 | 那是使用者的业务本身；框架在这里给"标准答案"只会变成约束 | ADR-004 承诺纪律元原则 |
| 认证体系本身（登录、令牌签发、会话存储） | 框架只**消费**已解析的操作者；身份**来源**属接入口（`identity` 条目留缝） | who-is-operating 边界 |

## 二、留缝不预设（答案已交付，策略由真实项目裁）

- 软删除 / 乐观锁——审计四件套之外的行策略（[data-access](problems/data-access.md) 取舍段）；
- 列表行过滤 / 查询语言——属 adapter 的查询优化（data-access 边界）；
- 分布式缓存语义——进程内承诺同键只装一次，跨进程互斥是 `lock` 条目的事（[cache](problems/cache.md) 边界）；
- 采样策略——高频事件记不记由调用方决策（[what-happened](problems/what-happened.md) 边界）；
- 读取失败的投影形态——单资源 404 还是统一 400，一个服务内自定一种（[接入清单](INTEGRATION.md) §6）。

## 三、待答（open，以 catalog 为准）

`open` 的意思是"已立目、还没答案"，**不是"不答"**。哪些 open 会升级成答案由准入三关裁（ADR-006）；
清单不在此复述，机器视角见 [catalog/problems.json](../catalog/problems.json)。

## 判据

一个"不答"要想站住，必须过 ADR-004 的三问：**词能兑现吗？目标能被测试守住吗？差异经得起对标吗？**
三问有一个答"不能"，就只能留缝或待答，不许写成承诺——也不许写成含混的"暂不支持"。
