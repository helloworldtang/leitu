# ADR-003 架构风格：分层组织，微内核组装

状态：已接受（2026-09-07）

## 背景

"分层还是微内核"是本项目的第一个架构问题。结论：两者不在同一轴上竞争，各答一题。

## 决策

**分层组织（compile-time），微内核组装（runtime）。**

- **分层**回答"仓库里的代码怎么组织"：starter → adapter → capability → core，编译期依赖单向向下
- **微内核**回答"应用怎么组装出来"：以 core 为内核，能力与业务模块作为可插拔单元挂载；模块协作必经 OperationDispatcher（内核通信），不许直插对方 internal
- 累土是"**宿主之上的微内核**"：机制与策略分离的微内核思想全保留；模块加载与生命周期委托宿主（Spring Boot），故不自称 runtime

## 判据核对

微内核适用判据：product-based（多版本、按需组合安装）✓；功能以插件形式持续增长（= 答案库越用越厚）✓；核心系统与业务无关 ✓。

## OS 同构（core/capability 关系为何不奇怪）

| 累土 | 操作系统 | 角色 |
|---|---|---|
| 端口面 | 系统调用接口 | 共同编程的稳定面 |
| OperationDispatcher | 内核 IPC | 模块间通信 |
| capability | 系统服务 | 端口的**服务侧**（实现端口） |
| 业务代码 | 应用程序 | 端口的**应用侧**（消费端口） |
| adapter | 驱动 | 绑定中间件 |
| starter | 发行版组装 | 打包成可启动系统 |

所有层面向内核编程——纯分层叙事看不出 capability 服务于谁，微内核叙事一目了然。
