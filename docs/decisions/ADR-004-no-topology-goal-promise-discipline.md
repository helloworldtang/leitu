# ADR-004 删除部署拓扑目标；承诺纪律

状态：已接受（2026-09-07）

## 背景

早期设计曾以"单体↔微服务零代码切换"为目标。复审结论：拆库拆表、团队组织约束都在框架控制面之外，框架无法也不应为此负责。降级为"可迁移"同样站不住——那只是把夸大的承诺缩小一号，仍然承诺了控制面之外的事。

## 决策

- **部署拓扑目标整体删除**：累土不承诺单体/微服务切换，也不承诺"可迁移"。远程调用是应用自己的事（Spring 自带客户端），框架保持沉默
- OperationDispatcher 重新定义为**纯 in-process 模块间通信机制**（上下文传播/鉴权/观测在环）
- 连带收益："跨模块怎么调"的答案从**有条件**（看部署形态）变为**无条件唯一**——条件分支是非确定性之源，删掉它，答案更纯

## 承诺纪律（元原则）

框架只承诺能被机器守护的事：

1. **词要能兑现**——kernel 一词承诺了兑现不了的运行时语义，退役（ADR-001）
2. **目标要能被测试/CI 守住**——拓扑切换无法被任何测试守护，删除（本 ADR）
3. **差异要经得起对标**——MCP 暴露因竞品以注解免费做掉八成而降级为路线图（搜证结论）

三案同源，一以贯之。
