## 六、没验证什么

| 项 | 原因 | 建议由谁补验 |
|---|---|---|
| 匿名模式（`demo.trust-request-headers=false`）下的 403 行为 | 验收没要求；主配置为 true，未再起第二个 context | 父 agent 可加 `@SpringBootTest(properties="demo.trust-request-headers=false")` 复跑；金样本 `DemoIdentityDefaultTest` 有同款断言 |
| 读取端点的判定链（data:read / 匿名读） | 金样本 `get` 不判定，我照写；验收第 5 条只要求隔离结果 | 若要补，按 data-access「二、机制」的 `DataStores.guarded` 包存取器，并补"匿名读 403"用例 |
| 缺参 / 类型错误（如 `priceCents=abc`）的响应形态 | 超出验收；Spring 默认会返回 400，但未必是 problem+json | 需要 `@RestControllerAdvice` 或 adapter-web 的全局处理；建议父 agent 用 curl 验证 |
| 重复 id（同租户 save 已存在）的插入/更新语义 | 未在验收内；`DataStore.save` 文档说"插入/更新"但没给业务层期望 | 用同 id 连续 POST 观察 200 与 `createdAt` 是否保留 |
| 删除、分页 `findAll(PageRequest)` | 任务只要求创建/读取两个端点 | 不在本次范围 |
| 系统错（500）脱敏投影 | 本服务没有 `/demo/boom` 等价端点 | 可加一个抛 `IllegalStateException` 的端点验证 `kind=SYSTEM` + 通用 detail |
| 真实数据库（MySQL/PostgreSQL） | 只用了 H2 内存；adapter 的 SQL 方言/类型映射未覆盖 | 属 adapter 层验证，需外部库或 Testcontainers |
| 重启后数据 | H2 `mem` + `DB_CLOSE_DELAY=-1`，重启即失（预期） | 若要持久化，换 file/H2 或真实库再验 |
| 跨线程/异步上下文传播 | 未写异步代码 | who-is-operating 边界已说明由 binder 实现负责 |

| `./mvnw verify` | 任务只要求 `mvn test`；且本工程不是 leitu 仓库模块，`verify` 不含仓库的 catalog/markdown 检查 | 父 agent 若按仓库习惯要求，可复跑 verify（预计与 test 同结果） |
