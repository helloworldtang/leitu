# 任务 01-对照 · 同一个服务，不用累土（对照组专用）

> 本卡只用于**对照组采样**：测量"同一个任务，在没有 leitu 可用的条件下"的四项读数，
> 与任务 01（v2）的读数并列对照。它不进正常采样序列，读数不作为 leitu 的基线，只作为对照。
> 与 `01-entity-crud-service.md` 的唯一共同点是**行为验收**；差异是：不提供任何仓库资料、禁止引入 leitu。

## 目标

在空目录创建一个可运行的 Spring Boot 业务服务：一个实体（业务字段自定 ≥1）+ 该实体的存取 + 创建 / 读取两个端点，并满足下面第 2～4 条行为。

## 环境

- 只允许使用 **Spring Boot 官方 starter** 与官方文档（可上网查官方资料）；测试库（JUnit / AssertJ / MockMvc）不受限；
- **禁止**：引入 `leitu` / `累土`（groupId `cn.youhuale`）或任何非 Spring 官方的框架 / 工具库；
  阅读 leitu 仓库的任何文件（docs / examples / skills / README 一律不看）；
- 除任务卡与本机工具外，没有其他参考资料——**这就是对照组的定义**。

## 验收（全过才算完成；措辞框架中立）

1. `mvn test` 全绿，且**第 2～4 条行为各有至少一个测试断言**——零测试时 surefire 也会绿，那种绿不计入「一次绿灯」；
2. 审计：创建后读回，响应里能看到"这条数据是谁创建的"（= 请求里的操作者身份）；
3. 守卫：非授权主体创建 → 403，错误体是机器可读 JSON，含**错误标识**与 **traceId**；
4. 隔离：租户 A 写入的数据，租户 B 读同一 id → **读不到**（非 200 且非 500）；
5. 登记：完成率 / 一次绿灯 / 时长 / 歧义点清单（格式同任务 01 v2：`位置 | 我猜了什么 | 依据是什么`）。

## 读数口径（与任务 01 完全一致，保证可比）

- 完成率：上述验收逐条自评，能自证给命令，不能自证明说未验证；
- 一次绿灯：首次 `mvn test` 是否全绿；
- 时长：`date +%s` 自任务开始至首次测试结束；
- 歧义点：每一次"任务卡没说清、我不得不猜"都记一条——**这条清单与 leitu 侧同样重要**：
  leitu 侧的答案消灭了哪些猜，对照组的清单就是直接证据。
